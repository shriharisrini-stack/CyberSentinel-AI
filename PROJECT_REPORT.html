ABSTRACT

Electronic mail remains the primary conduit for academic, enterprise, and personal communication. Consequently, it serves as the initial entry vector for over 85% of modern cyber incidents, principally executed through phishing, Business Email Compromise (BEC), credential harvesting, and malicious hyperlink redirection. Conventional spam filtering systems operate largely as opaque black boxes, classifying messages without revealing the underlying indicators of compromise (IoCs). As a result, students and novice computer users frequently succumb to lookalike domains, deceptive subdomains, and obfuscated URLs due to a complete absence of transparent, explainable feedback.

This project presents CyberSentinel AI — Email Threat Detection System, a responsive, explainable web-based security analytics platform developed using Python and the Flask framework. Users can input sender email addresses and suspicious message bodies into a Security Operations Center (SOC) telemetry dashboard. The back-end engine applies multi-vector heuristic rules to scrutinize sender domain reputation, high-risk disposable top-level domains (TLDs), psychological urgency patterns, and financial coercion tactics.

Furthermore, the system integrates a Safe Offline URL Forensic Analyzer that extracts hyperlinks and inspects them strictly offline without initiating dangerous external connections. The engine evaluates direct IPv4 hosts, URL shorteners, brand typosquatting, and subdomain deception. The platform calculates an explainable, normalized Risk Score (0–100) and maps findings to Safe, Suspicious, or High Risk tiers, accompanied by granular explanations and actionable remediation steps. CyberSentinel AI bridges the gap between academic theory and practical defensive cybersecurity for undergraduate students.

Keywords: Email Threat Detection, Phishing Detection, Heuristic Analysis, URL Forensics, Explainable Cybersecurity, Social Engineering, Python, Flask.

CHAPTER 1
INTRODUCTION
1.1 Background

Email represents the foundational backbone of digital communication across academia, business, and daily life. With billions of emails exchanged daily, email architecture remains inherently trusting, as the original Simple Mail Transfer Protocol (SMTP) lacked native identity verification. Cyber adversaries exploit this architectural weakness to conduct phishing, impersonation, and social engineering attacks, causing severe financial and operational damage worldwide.

1.2 Overview of the Project

CyberSentinel AI — Email Threat Detection System is a lightweight, explainable cybersecurity web application developed with Python and Flask. The platform enables users to submit sender email addresses and suspicious message text for automated multi-vector heuristic analysis. The system inspects sender anomalies, detects psychological coercion tactics, performs safe offline URL deconstruction, and calculates a normalized 0–100 Risk Score with full explainability.

1.3 Need for the Project
  • Exploitation of Human Trust: Attackers target emotional urgency rather than system vulnerabilities.
  • Opaque Spam Filters: Traditional email filters tag spam without educating users on the underlying threat indicators.
  • Complex Enterprise Systems: Commercial Security Email Gateways require expensive corporate routing and licenses.
  • Safe Educational Sandbox: IT students require an offline environment to safely study phishing heuristics without malware execution risk.
1.4 Scope of the Project

The project delivers a standalone web application featuring interactive form inputs, 1-click test datasets, transparent rule-based scoring, offline URL analysis, and a RESTful API. It operates entirely locally on Windows 11 without accessing private inboxes or sending outbound emails, guaranteeing absolute privacy and safety.

CHAPTER 2
PROBLEM STATEMENT AND OBJECTIVES
2.1 Problem Statement

Email users face persistent social engineering attacks where attackers manipulate cognitive biases—such as urgency, fear of financial loss, or curiosity—to extract sensitive passwords or induce wire transfers. Existing desktop and cloud spam filters operate as opaque black boxes, providing zero visibility into why a message was classified as dangerous. Novice users cannot distinguish legitimate corporate domains from typosquatted variations (e.g., paypa1-support.xyz) or recognize lookalike subdomains (e.g., login.microsoft.com.attacker.com). There is an urgent need for an explainable, interactive email threat analysis system that educates users while evaluating threats safely offline.

2.2 Objectives
  1. Develop an intuitive web interface adhering to modern Security Operations Center (SOC) aesthetics.
  2. Implement regular-expression heuristic rules to detect credential harvesting and financial coercion.
  3. Analyze sender addresses for lookalike domains, free-mail brand impersonation, and disposable TLDs.
  4. Build a safe offline URL forensic engine to inspect direct IP hosts, URL shorteners, and deceptive subdomains without external network pings.
  5. Formulate an explainable Risk Score (0–100) that avoids false convictions on single isolated indicators.
  6. Incorporate preloaded 1-click sample emails covering phishing, BEC, scams, and legitimate baselines.
  7. Deliver actionable incident response remediation advice based on calculated risk levels.
  8. Provide a lightweight REST API endpoint for automated and programmatic analysis.

CHAPTER 3
EXISTING SYSTEM AND PROPOSED SYSTEM
3.1 Existing System

Traditional defenses rely on commercial Secure Email Gateways (SEGs) or standard desktop spam folders. These systems suffer from significant educational and operational limitations:

  • Opaque classification: Messages are marked as "Spam" without line-by-line justification.
  • High barrier to entry: Enterprise email gateways require complex MX record changes and paid subscriptions.
  • Unsafe link testing: Users must manually open links in a browser to inspect them, risking drive-by malware.
  • Binary scoring: Fails to teach students the subtle differences between weak caution flags and critical threats.
3.2 Proposed System

The proposed CyberSentinel AI replaces opaque filtering with a transparent, educational workflow: Telemetry Ingestion → Heuristic Parsing → Safe Offline URL Forensics → Weighted Synthesis → Explainable Reporting.

5.3 Workflow Description

The workflow consists of five stages: (1) Input Ingestion via form or API; (2) Text normalization and URL extraction; (3) Parallel execution of sender inspection, text pattern matching, and safe offline URL forensics; (4) Multi-indicator scoring synthesis; and (5) Report rendering with visual indicators and incident response steps.

5.4 Key Heuristic Modules
  • Sender Inspector (`inspect_sender`): Identifies brand typosquatting, high-risk TLDs, and free webmail impersonation.
  • Text Pattern Matcher (`THREAT_PATTERNS`): Scans for credential harvesting, urgent payment demands, and fear tactics.
  • URL Forensic Engine (`analyze_single_url`): Evaluates direct IP links, URL shorteners, and subdomain brand spoofing offline.
  • Scoring Synthesizer (`analyze_email`): Aggregates weighted scores, caps at 100, and formulates defensive actions.

6.2 Implementation Details

The application follows a client-server architecture. Flask routes handle GET requests for the main page and POST requests for analyzing email text. The user interface uses a cybersecurity dark theme with glassmorphism and dynamic animations. The URL forensic engine operates purely offline, decomposing links into components and checking them against known threat indicators without initiating network requests.

6.3 Safe Offline URL Forensic Engine

The URL forensic engine evaluates each extracted link using multi-indicator rules:

  • Direct IPv4 Detection: Regex ^(\d{1,3}\.){3}\d{1,3}$ detects links hosting on raw IP addresses.
  • URL Shortener Detection: Checks hostnames against known shorteners (bit.ly, tinyurl.com). Flagged as a single indicator of caution rather than conclusive proof of malware.
  • Subdomain Brand Deception: Detects instances where high-value brands (e.g. `microsoft`) appear in subdomains while pointing to a foreign registered domain.
  • Typosquatting Homoglyphs: Flags character substitutions such as `paypa1`, `micros0ft`, and `amaz0n`.

CHAPTER 7
RESULTS AND OUTPUT SCREENS

The working prototype was evaluated across five diverse email scenarios representing different threat vectors:

Scenario 1: PayPal Account Suspension (Phishing Attack)
  • Sender: security-alert@paypa1-support-portal.xyz
  • Hyperlink: http://192.168.1.105/paypal-login/verify.php
  • Output: Risk Score = 95 / 100 (Dangerous Phishing Probability).
  • Flagged Indicators: Brand typosquatting (`paypa1`), high-risk TLD (`.xyz`), direct IPv4 host, unencrypted HTTP on login path, credential harvesting language, and 24-hour urgency.
Scenario 2: CEO Wire Transfer Fraud (Business Email Compromise)
  • Sender: ceo.executive.office@gmail.com
  • Hyperlink: None (Text-only social engineering)
  • Output: Risk Score = 75 / 100 (Dangerous Phishing Probability).
  • Flagged Indicators: Free webmail impersonating corporate leadership, immediate wire transfer demand, overdue invoice pressure. Correctly reports 0 URLs detected.
Scenario 3: Lottery Jackpot Scam (Single URL Shortener Indicator)
  • Sender: claims-department@euromillions-promo.tk
  • Hyperlink: http://bit.ly/claim-jackpot-reward-2026
  • Output: Risk Score = 55 / 100 (Suspicious / Medium Threat).
  • URL Verdict: Marked as Suspicious (1 Indicator - Exercise Caution). The engine avoids false accusations, explicitly noting that a shortener alone requires verification rather than definitive proof of malice.
Scenario 4: Microsoft 365 Subdomain Spoofing
  • Sender: admin@office365-security-alert.xyz
  • Hyperlink: http://login.microsoft.com.account-verification-portal.xyz/auth/reset
  • Output: Risk Score = 90 / 100 (Dangerous Phishing Probability).
  • URL Verdict: Marked as High Risk (3 Correlated Threat Indicators): Subdomain deception (`login.microsoft.com` prefix on foreign base domain), risky TLD (`.xyz`), and unencrypted HTTP on an auth path.
Scenario 5: Legitimate Corporate Project Update (Safe Baseline)
  • Sender: sarah.jenkins@acmecorp.com
  • Hyperlink: https://sharepoint.acmecorp.com/teams/q3-roadmap
  • Output: Risk Score = 0 / 100 (Safe / Low Threat). 0 warnings, clean URL.

CHAPTER 9
IMPACT, CHALLENGES AND FUTURE ENHANCEMENTS
9.1 Impact Analysis
  • For IT Students: Provides transparent insight into how social engineering and deceptive link structures operate.
  • For Organizations: Serves as a zero-cost educational simulator to train staff on email phishing awareness.
  • For Defensive Security: Demonstrates that explainable heuristics provide actionable intelligence without complex cloud dependencies.
9.2 Challenges Faced
  • Punctuation Stripping in URLs: Cleaning trailing periods and brackets from conversational text without truncating valid URL parameters.
  • Subdomain vs. SLD Discrimination: Differentiating legitimate multi-level domains (e.g. `teams.microsoft.com`) from deceptive subdomains (`microsoft.com.attacker.com`) offline without a live WHOIS database.
  • False Positive Mitigation: Implementing single-indicator caution labeling to prevent shorteners from immediately triggering false malware alarms.
9.3 Future Enhancements
  • Integration of Machine Learning classifiers (Naive Bayes, Random Forest) trained on public datasets.
  • Header parsing for raw .eml files to inspect SPF, DKIM, and DMARC authentication records.
  • Sandboxed screenshot rendering using headless browser containers.
  • Packaging as a browser extension for direct client-side inbox protection.
